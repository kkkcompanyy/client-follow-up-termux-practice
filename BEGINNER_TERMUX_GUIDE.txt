CLIENT FOLLOW-UP — BEGINNER FULL DISASTER-RECOVERY MANUAL
========================================================

Last verified: 2026-10-11

PURPOSE
-------
This manual is written for the situation where:

- You have a new/fresh Termux installation.
- You remember almost nothing about the setup.
- Your current app stopped working, or you changed phones.
- You still have this backup folder:

    /sdcard/Download/NEW APP BACKUPP

- You want to rebuild the Client Follow-Up website from zero.
- You want to run it locally.
- You want to expose it to the internet with ngrok OR Cloudflare Tunnel.
- You want to know exactly WHICH terminal/session to use for each command.

This guide is intentionally beginner-friendly and repetitive.

IMPORTANT SECURITY NOTE
-----------------------
Do NOT write passwords, Flask secret keys, ngrok authtokens, Cloudflare tunnel tokens,
or other private credentials into this README.

If a command below shows:

    <YOUR_AUTHTOKEN>

or:

    <YOUR_TUNNEL_TOKEN>

replace it only in your terminal when needed.

Do not paste your real token into public chats or public GitHub repositories.

============================================================
PART 0 — UNDERSTAND THE SETUP BEFORE TOUCHING ANYTHING
============================================================

Your setup has THREE separate pieces:

1) THE FLASK WEBSITE
   Runs in NORMAL TERMUX.
   Example command:

       cd ~/checker-lab
       python app.py

   It listens on:

       http://127.0.0.1:5000

2) THE DATABASE
   File:

       ~/checker-lab/clients.db

   This is where your real client information is stored.

3) THE PUBLIC TUNNEL
   This makes your local Flask website reachable from the internet.

   You can use ONE of these:

       ngrok

   OR:

       cloudflared

   You do NOT need both running at the same time.

In the setup we used, ngrok runs inside an Ubuntu environment installed inside Termux.
For simplicity, this manual also recommends installing cloudflared inside that same Ubuntu environment.

============================================================
PART 1 — WHICH PROJECT FILES ARE REALLY IMPORTANT?
============================================================

Your main live project folder is:

    ~/checker-lab

The full backup folder is:

    /sdcard/Download/NEW APP BACKUPP

IMPORTANT FILES:

A) ONE Python app version

You can run any ONE of these:

    app.py
    app_pro_theme.py
    cobra_finalwork.py
    cobra_astra.py            <-- example future version

Only one of them needs to run at a time.

B) Database

    clients.db

    static/no_refresh.js

This is part of the working Quick Action/no-refresh behavior.

D) Cobra image

The cobra versions use:

    static/cobra-reference.png

The working cobra versions directly reference:

    /static/cobra-reference.png

If this image is missing, the Python app may still start,
but the cobra design/background will be broken or incomplete.

E) Other static files

Keep the entire:

    static/

folder.

BEST PRACTICE:
Do not try to save only the minimum.
Keep the ENTIRE NEW APP BACKUPP folder.

PART 2 — INSTALL TERMUX CORRECTLY
============================================================

Recommended sources for Termux:

- F-Droid
- Official Termux GitHub releases

The official PRoot-Distro project recommends installing Termux from F-Droid
or Termux GitHub releases.

============================================================
PART 3 — FIRST TERMUX SETUP
============================================================

STEP 1 — Give Termux storage access

In NORMAL TERMUX run:

    termux-setup-storage

Android may ask for permission.

Tap:

    Allow

If Termux says ~/storage already exists, that is normally okay.

Check that Downloads is visible:

    ls /sdcard/Download

You should be able to see:

    NEW APP BACKUPP

If you do not see it, stop here and fix storage permission first.

------------------------------------------------------------
STEP 2 — Update Termux packages
------------------------------------------------------------

Run:

    pkg update -y

Then:

    pkg upgrade -y

This can take a few minutes.

------------------------------------------------------------
STEP 3 — Install the basic tools
------------------------------------------------------------

Run this in NORMAL TERMUX:

    pkg install -y python git curl wget nano unzip tar proot-distro sqlite lsof

What these are for:

    python         = runs the Flask app
    git            = useful for source/code work
    curl           = tests the local API and downloads files
    wget           = downloads files
    nano           = simple text editor
    unzip          = extracts ZIP files
    tar            = extracts .tar.gz files
    proot-distro   = installs/runs Ubuntu inside Termux
    sqlite         = optional database inspection tool
    lsof           = helps find which process is using port 5000

Check Python:

    python --version

Check pip:

    pip --version

------------------------------------------------------------
STEP 4 — Install Flask
------------------------------------------------------------

Run:

    pip install flask

When finished, check:

    python -c "import flask; print(flask.__version__)"

If it prints a Flask version, Flask is installed.

PART 7 — TEST THE API BEFORE STARTING A TUNNEL
============================================================

You need a SECOND Termux session because the first session is busy running Flask.

BEGINNER TIP:
In Termux, open the side drawer/menu and create a NEW SESSION.
Do not stop Flask in the first session.

In the second NORMAL TERMUX session run:

    curl http://127.0.0.1:5000/api/health

then Flask is NOT reachable.

    python app.py

or another version is still running.

DO NOT troubleshoot ngrok or Cloudflare until this local curl works.

PART 9 — INSTALL NGROK INSIDE UBUNTU
============================================================

This section is:

    INSIDE UBUNTU

If you are not inside Ubuntu yet, from NORMAL TERMUX run:

    proot-distro login ubuntu

Check:

    whoami

Expected:

    root

------------------------------------------------------------
STEP 1 — Add the official ngrok APT repository
------------------------------------------------------------

Run:

    curl -sSL https://ngrok-agent.s3.amazonaws.com/ngrok.asc | tee /etc/apt/trusted.gpg.d/ngrok.asc >/dev/null

Then:

    echo "deb https://ngrok-agent.s3.amazonaws.com bookworm main" | tee /etc/apt/sources.list.d/ngrok.list

Then:

    apt update

Then:

    apt install -y ngrok

------------------------------------------------------------
STEP 2 — Verify ngrok
------------------------------------------------------------

Run:

    ngrok version

You should see the installed ngrok version.

------------------------------------------------------------
STEP 3 — Add your ngrok account authtoken
------------------------------------------------------------

You need an ngrok account.

Open the ngrok dashboard in your browser and find your Authtoken.

DO NOT save the token in this README.

INSIDE UBUNTU run:

    ngrok config add-authtoken "<YOUR_AUTHTOKEN>"

Replace only:

    <YOUR_AUTHTOKEN>

with your real token.

After this, ngrok stores the authentication configuration for you.

------------------------------------------------------------
STEP 4 — Make sure Flask is running FIRST
------------------------------------------------------------

Remember:

FLASK runs in NORMAL TERMUX.

ngrok runs INSIDE UBUNTU.

You therefore need two Termux sessions:

SESSION 1 — NORMAL TERMUX:

    cd ~/checker-lab
    python app.py

SESSION 2 — UBUNTU:

    proot-distro login ubuntu

Then ngrok runs in Session 2.

Before starting ngrok, you can test from Ubuntu:

    curl http://127.0.0.1:5000/api/health

Because PRoot shares the Android network environment,
this should reach the Flask process running in normal Termux.

------------------------------------------------------------
STEP 5 — Run your reserved/static ngrok URL
------------------------------------------------------------

INSIDE UBUNTU:

    ngrok http --url=splatter-conch-theology.ngrok-free.dev http://127.0.0.1:5000

Keep that terminal open.

Your public URL is:

    https://splatter-conch-theology.ngrok-free.dev

Open it from another device/browser.

------------------------------------------------------------
STEP 6 — Temporary ngrok URL instead

If you do not want to use the reserved URL:

PART 11 — INSTALL CLOUDFLARED INSIDE UBUNTU
============================================================

Cloudflare Tunnel is an ALTERNATIVE to ngrok.

You do NOT need ngrok running when using cloudflared.

This manual installs cloudflared inside the same Ubuntu environment
to keep the setup easy to remember.

Enter Ubuntu from NORMAL TERMUX:

    proot-distro login ubuntu

Everything below is:

    INSIDE UBUNTU

------------------------------------------------------------
STEP 1 — Install Cloudflare package signing key
------------------------------------------------------------

Run:

    mkdir -p --mode=0755 /usr/share/keyrings

Then:

    curl -fsSL https://pkg.cloudflare.com/cloudflare-main.gpg | tee /usr/share/keyrings/cloudflare-main.gpg >/dev/null

------------------------------------------------------------
STEP 2 — Add Cloudflare APT repository
------------------------------------------------------------

Run:

    echo "deb [signed-by=/usr/share/keyrings/cloudflare-main.gpg] https://pkg.cloudflare.com/cloudflared any main" | tee /etc/apt/sources.list.d/cloudflared.list

Then:

    apt-get update

Then:

    apt-get install -y cloudflared

------------------------------------------------------------
STEP 3 — Verify cloudflared
------------------------------------------------------------

Run:

    cloudflared --version

If it prints a version, installation worked.

============================================================
PART 12 — RUN A CLOUDFLARE QUICK TUNNEL
============================================================

A Quick Tunnel is the easiest Cloudflare method.

IMPORTANT:
- No Cloudflare account is required for a Quick Tunnel.
- No domain is required.
- The public URL is temporary.
- It normally changes when you restart cloudflared.

FIRST:
Make sure Flask is running in NORMAL TERMUX:

    cd ~/checker-lab
    python app.py

or the visual version you want.

Test:

    curl http://127.0.0.1:5000/api/health

Now, in a SECOND Termux session:

    proot-distro login ubuntu

INSIDE UBUNTU run:

    cloudflared tunnel --url http://127.0.0.1:5000

cloudflared will print an address similar to:

    https://something-random.trycloudflare.com

Open that URL in a browser.

Anyone who has that URL can reach the local web app while the tunnel is running.

To stop cloudflared:

    CTRL + C

============================================================
PART 14 — OPTIONAL: PERMANENT CLOUDFLARE TUNNEL
============================================================

This is NOT required for the current app.

Use this only if one day you want a fixed Cloudflare hostname/domain.

For a normal named/permanent Cloudflare Tunnel, Cloudflare generally requires:

- a Cloudflare account
- a domain managed by Cloudflare
- a tunnel configuration or token

Cloudflare's current dashboard flow is:

    Cloudflare Dashboard
    -> Networking
    -> Tunnels
    -> Create Tunnel

Cloudflare then provides a tunnel token or installation command.

IMPORTANT FOR PROOT/ANDROID:
Do NOT blindly follow Linux instructions that install cloudflared as a systemd service.

A PRoot Ubuntu environment on Android does not behave like a normal always-on Ubuntu server.

For this phone setup, manually running the tunnel process is simpler.

If Cloudflare gives you a tunnel token, the manual-run pattern is generally:

    cloudflared tunnel run --token "<YOUR_TUNNEL_TOKEN>"

Do not save that token inside this README.

============================================================
PART 18 — ANDROID APP RELATIONSHIP
============================================================

The Android app is a separate project.

The website/backend uses:

    clients.db

The Android app communicates with the Flask REST API.

That means:

- Web marks a client Called.
- Flask updates clients.db.
- Android sync sees the updated data.
- Another website theme also sees the same data.

DO NOT change the API routes just because you are changing the website design.

Important API routes include:

    /api/health
    /api/login
    /api/clients
    /api/stats
    /api/sync
    /api/clients/add
    /api/clients/<id>/toggle
    /api/clients/<id>/status
    /api/clients/bulk
    /api/clients/import

============================================================
PART 19 — PROTECTED WORKING WEBSITE BEHAVIOR
============================================================

Do not casually change:

    static/no_refresh.js

Important protected behavior:

- Quick Action does not cause the old bad full-page refresh/jump.
- Category remains selected.
- Bulk actions keep category.
- Called At timestamp works.
- Mark Called sets a local timestamp.
- Mark Not Called clears Called At.
- Android API remains compatible.

If a redesign breaks any of this, restore/compare against the working Python backup.

PART 20 — COMMON PROBLEMS AND EXACT FIXES
============================================================

PROBLEM:
    python: command not found

FIX:

    pkg install -y python


PROBLEM:
    ModuleNotFoundError: No module named 'flask'

FIX:

    pip install flask


PROBLEM:
    Port 5000 already in use

CHECK:

    lsof -i :5000

Most likely another Flask version is still running.

Go to its session and press:

    CTRL + C

Then start the version you want.


PROBLEM:
    curl http://127.0.0.1:5000/api/health
    says Connection refused

FIX:
Flask is not running.

Run in NORMAL TERMUX:

    cd ~/checker-lab
    python app.py


PROBLEM:
    ngrok opens but says upstream connection failed

FIRST TEST:

    curl http://127.0.0.1:5000/api/health

Do this locally before blaming ngrok.


PROBLEM:
    cloudflared starts but public page fails

FIRST TEST:

    curl http://127.0.0.1:5000/api/health

Then test INSIDE UBUNTU:

    curl http://127.0.0.1:5000/api/health

If Ubuntu cannot reach Flask, fix local connectivity before the tunnel.


PROBLEM:
    ngrok command not found INSIDE UBUNTU

Run:

    apt update
    apt install -y ngrok

If the ngrok repository was never added, repeat PART 9.


PROBLEM:
    cloudflared command not found INSIDE UBUNTU

Repeat PART 11.


PROBLEM:
    proot-distro command not found

In NORMAL TERMUX:

    pkg install -y proot-distro

    Ubuntu is not installed

Check:

    proot-distro list

PROBLEM:
    Website starts but cobra background is missing

Check:

    ls -lh ~/checker-lab/static/cobra-reference.png

    /static/cobra-reference.png

PART 23 — OPTIONAL PHONE STABILITY TIPS
============================================================

Long-running Flask/tunnel processes can stop if Android aggressively kills Termux.

Helpful ideas:

- Keep Termux open while testing.
- Avoid swiping Termux away from recent apps.
- Disable aggressive battery optimization for Termux if Android keeps killing it.
- Keep the phone connected to stable power for long sessions.

Termux also supports a wake lock command on many installations:

    termux-wake-lock

When finished:

    termux-wake-unlock

If these commands are unavailable, simply skip them.
